# PlanPM – Backend

Backend responsible for fetching, processing, and storing class schedules from the Virtual Dean's Office of the Maritime University of Szczecin into a Supabase database.

---

## Project Structure

```
backend/
├── main.py                  # Entry point – runs the full pipeline
├── mapper/                  # Step 1 – detects active schedule IDs
├── scrapper/                # Step 2 – scrapes schedules over HTTP (no browser)
├── parser/                  # Step 3 – normalises raw data into JSON
├── json2db/                 # Step 4 – uploads data to Supabase
├── structure_updater/       # Separate pipeline – updates university structure
├── admin/                   # Local Flask admin panel (news, pipeline, stats, settings)
├── mcp_server/              # MCP server – drive the backend from an agent
├── output/                  # JSON files generated by the pipeline (gitignored)
└── logs/                    # Logs from each step (not committed)
```

---

## Pipeline – Class Schedules

```
Mapper → Scrapper → Parser → json2db
```

### 1. `mapper/`
Iterates over a range of IDs and checks which ones correspond to active schedule pages (plain HTTP GET, no browser required).

**Output:** `output/mapper.json` – a dictionary `{ "flow_id": "schedule name", ... }`

### 2. `scrapper/`
For each ID from the mapper, fetches the schedule over plain HTTP (DevExpress callback, no browser) and scrapes the timetable rows. ~2s per plan.

**Output:** `output/scrapper.json` – a flat list of schedule rows with Polish field names (`Sala`, `Prowadzący`, `Przedmiot`, etc.)

### 3. `parser/`
Normalises raw scrapper data – deduplicates entries, parses teachers, rooms and buildings, converts dates to UNIX timestamps, and builds cross-reference indices.

**Output:** `output/parser.json` – structured JSON with keys `programs`, `classes`, `teachers`, `rooms`, `building`, `subjects`, `teachersclasses`

### 4. `json2db/`
Reads `parser.json` and upserts all entities into Supabase tables (safe to run multiple times).

## Pipeline – University Structure

### `structure_updater/`
A standalone script that scrapes the university hierarchy (Faculties → Degree Courses → Specialisations) from the website and writes it to Supabase.

## Admin Panel

### `admin/`
A local, loopback-only Flask panel (replaces the old `news_tool`). Tabs:
- **News** — add/edit/delete news posts, image upload, message types (`info`/`warning`/`alert`)
- **Pipeline** — run the full pipeline or any single step with live streamed logs
- **Statistics** — Google Play (Android) and App Store Connect (iOS) metrics + reviews
- **Settings** — switch the target database (prod/test)

**Run:**
```bash
python -m admin.app
# opens at http://127.0.0.1:5050 (localhost only)
```

**Requirements:** `SUPABASE_URL` and `SUPABASE_SERVICE_KEY` in `.env` (service role key). Stats need read-only Google/Apple credentials; the panel still runs without them.

### MCP Server (`mcp_server/`)
Exposes the pipeline / news / log tools to an agent over MCP:
```bash
python -m mcp_server.server
```

## Running

### Full pipeline

```bash
python main.py                          # HTTP scrapper, 10 workers (default)
python main.py --workers 20             # increase parallelism
```

The full pipeline refuses to clear the DB if parsing produced suspiciously few
classes (a failed scrape), so a site outage can't wipe the live schedule.

### Re-upload without re-scraping

If `output/parser.json` is already up to date, skip the scraping steps:

```bash
python -m json2db.json2db --input ./output/parser.json --clear
```

### Individual steps

Each module can be run independently from the command line.

**json2db** – upload data to the database:
```bash
python -m json2db.json2db --input ./output/parser.json
python -m json2db.json2db --input ./output/parser.json --clear      # clear DB before writing
python -m json2db.json2db --input ./output/parser.json --dry-run    # preview without writing to DB
```

**structure_updater** – update university structure (scrapes from the website):
```bash
python -m structure_updater.structure_updater              # scrape + write to DB
python -m structure_updater.structure_updater --dry-run    # preview without writing
```

### Tests

```bash
pip install -e ".[dev]"       # installs pytest

pytest -m "not slow"          # fast tests (no network calls)
pytest -m slow                # tests requiring internet access
```

## Configuration

Create a `.env` file in the `backend/` directory:

```env
SUPABASE_URL=https://<project>.supabase.co
SUPABASE_SERVICE_KEY=<service_role_key>

# Optional – test database (used when .env_mode contains "test")
TEST_SUPABASE_URL=https://<test-project>.supabase.co
TEST_SUPABASE_SERVICE_KEY=<test_service_role_key>
TEST_DB_URL=postgresql://...              # for direct DB access in slow tests
```

### Switching between production and test database

The file `.env_mode` controls which credentials are used:

```bash
echo "test" > .env_mode   # use TEST_SUPABASE_* credentials
echo "prod" > .env_mode   # use SUPABASE_* credentials (default)
```

## Database Schema

### Schedule pipeline

```
programs ──────────────────────────────────┐
  id, name, programType, degreeLevel,      │
  language, academicYear, courseLength      │
                                            ▼
building ──┐                            classes
  id, name │                              id, subject, group, startTime,
           ▼                              endTime, room (FK), notes, program (FK)
         rooms                                 │
           id, name, building (FK)             │
                                        teachersclasses
teachers ──────────────────────────►      id, teachers (FK), classes (FK)
  id, fullName, title
```

| Table | Description |
|-------|-------------|
| `programs` | Degree programme (name, type, level, academic year) |
| `classes` | Individual class entry (subject, group, time, room) |
| `teachers` | Teaching staff |
| `teachersclasses` | N:M relation between teachers and classes |
| `building` | Buildings (Żołnierska, WChrobrego, etc.) |
| `rooms` | Rooms linked to a building |

### University structure pipeline

| Table | Description |
|-------|-------------|
| `faculties` | Faculties |
| `degree_courses` | Degree courses (FK → faculties) |
| `specialisations` | Specialisations (FK → degree_courses) |
